## 二、小程序侧改造（上线前必做）

1. **注册企业主体小程序并取得 AppID**
   - 在微信公众平台注册「小程序」，主体建议为运营单位/建设单位。
   - 类目建议：政务民生 → 交通，或 生活服务 → 其他（以微信审核为准）。
   - 将 `project.config.json` 的 `appid` 替换为正式 AppID。

2. **配置服务器合法域名（request / uploadFile / downloadFile）**
   - 在「开发 → 开发管理 → 开发设置 → 服务器域名」中配置后端 HTTPS 域名。
   - 三个域名均需配置：请求域名、上传域名、下载域名。
   - 必须为 **HTTPS**（微信要求），并具备有效证书。

3. **开启定位权限的隐私保护指引**
   - `app.json` 已声明 `scope.userLocation` 与 `requiredPrivateInfos: ["getLocation"]`。
   - 在平台「设置 → 服务内容声明 → 用户隐私保护指引」中补充收集位置信息的目的说明，否则 `wx.getLocation` 会被拦截。

4. **绑定微信身份（可选增强）**
   - 当前已用若依账号+密码登录；如需更顺滑，可后续接入 `wx.login()` 换 `openid`、`getPhoneNumber` 绑定平台账号。
   - 账号本身已由平台「账号管理 → 添加小程序账号」创建，无需再手填上报人。

5. **正式鉴权**
   - 小程序统一携带 `Authorization: Bearer <若依token>`（`utils/request.js`），`baseURL` 改为正式 HTTPS 域名。

## 三、后端侧改造（上线前必做）

0. ~~恢复登录验证码~~（已改为关闭）
   - 小程序走独立 `/miniapp/login`（免验证码，校验 `can_mini=1`）；Web 登录验证码当前**关闭**（`sys.account.captchaEnabled=false`），如需开启改回 `true` 即可。

1. **鉴权收紧**
   - 平台（Java 代理）走 `X-Service-Token`；上线设置 `AUDIT_API_TOKEN`（服务令牌）启用校验。
   - 小程序走若依 JWT，不再依赖任何开发期固定 Token。

2. **照片访问鉴权**
   - 当前 `GET /api/v1/patrol/photos/{photo_id}/file` 仅靠统一鉴权依赖；图片经 Java 代理 `download` 转发时带 `X-Service-Token`，小程序经 `downloadPhoto` 带 `X-Dev-Token`。
   - 上线需确认照片接口仅对已登录用户/有权限角色开放，避免公开可枚举下载。

3. **照片存储（可选）**
   - 当前存本地磁盘，多实例/备份需切换对象存储（OSS/MinIO），并把 `patrol_photos.file_path` 改为对象 Key。

4. **事件归属与台账**
   - 当前 `reporter_name` 为自由文本；上线后建议新增 `reporter_id` 关联平台用户，台账可按人统计。
   - 事件编号 `XC + 日期 + 序号` 为本地按日计数；如需跨实例部署，改为全局序号服务。

5. **AI 图像智能巡查（需求 1.2 预留点）**
   - 本轮为人工核查；架构上已把照片落库、核查结论独立成字段。
   - 后续可在 `add_photo` 后挂异步任务，调用图像模型识别「违规施工 / 超范围施工」等风险，回写事件的 `review_result` 建议值。

## 四、水印与照片处理说明

- 水印由后端 `audit_api/patrol.py` 的 `apply_watermark` 生成（Pillow），叠加时间/坐标/线路/上报人/事件编号，防代拍补拍。
- 中文字体按 `C:/Windows/Fonts/msyh.ttc` 等候选路径自动查找；Linux 部署需确认存在中文字体，否则水印中文会显示为方块。
- 小程序端 `chooseMedia` 已用 `sizeType: ['compressed']` 压缩；后端单张限 20MB、每事件最多 9 张。
